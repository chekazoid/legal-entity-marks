Имена таблиц задаёт WordPress, данные передаются через параметры или методы записи wpdb, структурные части SQL фиксированы либо выбраны из разрешённого списка. Потоки CSV относятся к ответу HTTP или к явно указанному файлу WP-CLI.

Эти аннотации не следует переносить на другие запросы без проверки. Для новых изменений нужно повторно проверять соответствующий SQL и границы входных данных.

## Изменения

- Статистика выключена по умолчанию. Сохранённое в старых версиях автоматическое включение не признаётся согласием. Согласие появляется только после сохранения формы с отмеченной галочкой и снимается сразу при её отключении.
- Регистрация сайта остаётся отдельным явным действием. Состав отправляемых полей показан до отправки. Перечень физических лиц по-прежнему выключен по умолчанию.
- Исправлены обработка слэшей и очистка входных полей, проверка nonce, экранирование вывода и параметры запросов поиска и отчётов.
- Запись содержимого и метаданных статей переведена на WordPress API с сохранением кавычек и слэшей в JSON. Полная очистка метаданных при удалении также использует API, чтобы сбрасывать постоянный кеш.
- Проверка TLS включена; официальный адрес ФСБ использует HTTPS. При ошибках сертификатов действует обычная цепочка резервных источников.
- Добавлены переводимые строки интерфейса и POT. Русский интерфейс сохранён, описание каталога подготовлено по-английски; [русская инструкция](readme-ru.md) вынесена отдельно.
- Исправлен некорректный JavaScript на странице без найденных ссылок. Список ресурсов получил поиск и постраничный вывод. На стенде с 5215 ресурсами размер страницы сократился примерно с 7.3 МБ до 164 КБ.
- Добавлены [описание сервиса и обработки данных](observer-service.md), GPL-лицензия и воспроизводимая сборка из явного списка файлов.

## Исправленная сверка реестров

По решению владельца полнота сверяется во всех категориях. Четыре основных
реестра переключаются одной транзакцией после проверки полного ответа,
числа строк и версии. Минюст проверяется до и после пагинации. Его
экстремистский перечень загружается из REST API. Наблюдатель отдаёт
совместимый `format=snapshot`: все строки относятся к одной версии
с подтверждённым числом записей. Исторические отсутствующие строки не
выдаются как текущие, явные даты исключения сохраняются.

Исчезнувшая запись остаётся в базе, получает неактивный статус и перестаёт
участвовать в маркировке. Дата юридического исключения не придумывается.
Связанные с ней ресурсы и старые результаты сканирования проверяют текущий
статус. Настройка маркировки бывших записей и ручное принуждение не
возвращают неизвестное отсутствующее название в активный перечень.
Алиасы, формулировки и история не удаляются; длинные имена сохраняются
целиком. После обновления сбрасывается кеш помеченных страниц, в том числе
в архивах больше прежнего предела в 5000 статей.

Физические лица остаются добровольной функцией. Новые записи не становятся
активными до окончания всех согласованных порций; финальная транзакция
публикует статусы и метаданные вместе. Ошибка сохраняет прежний активный
состав. Совпадение по одной фамилии не разрешалось и не добавлено.

Повторная живая проверка тестового экземпляра при отказе ведомств:

| Категория | Активных до сверки | После сверки | Активных вне среза |
|---|---:|---:|---:|
| Иноагенты | 1077 | 1040 | 0 |
| Экстремистские организации | 1184 | 625 | 0 |
| Террористические организации | 78 | 72 | 0 |
| Нежелательные организации | 442 | 442 | 0 |

Числа относятся к тестовому экземпляру 24.11.2026. Нормализация повторных
имён и существующий фильтр непригодных строк могут уменьшать число
распознанных записей относительно сырого ответа. Полные ответы получены из
реального канала; физические лица проверялись только на синтетических данных.
Повторная загрузка сохранила состав без ошибок. При одновременном отказе
официальных источников и канала все подтверждённые статусы и метаданные
остались прежними; зеркало и комплектные файлы не вернули старые названия.
Появилось ожидаемое предупреждение с источником «прежний подтверждённый список».
[Обезличенные результаты](review/registry-reconciliation.json).

Новые ручные добавления помечаются отдельно и не отключаются при отсутствии
в источнике. В прежних версиях происхождение не записывалось: неизвестные
старые ручные записи невозможно надёжно отличить от импортированных, они
тоже могут стать неактивными. Их данные сохраняются. Это ограничение описано
в русской инструкции и уведомлении об обновлении. Для безопасного переключения
нужны InnoDB у таблиц реестра и настроек; иначе сверка сохраняет прежние данные
и сообщает причину. API Наблюдателя обновлён отдельным коммитом `69daf95`,
полномочия токенов, базы и панель не изменены.
